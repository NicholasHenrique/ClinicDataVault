# Clinic DataVault

Portfolio project: a clinic/hospital scheduling data pipeline (appointments,
exams, status tracking and self-pay billing), built with a **medallion
architecture** on top of a **Data Vault 2.0** model.

## Architecture

```
GCS (raw)  →  Databricks Bronze  →  Silver: Raw Vault + Business Vault  →  Gold: Data Marts
Faker/Python   staging (as-is)      hub/link/sat · PIT/bridge/ref          star schema / BI
```

- **Bronze**: raw files generated by this repository (Python + Faker), landed in GCS as-is — no Data Vault modeling, no Databricks table. Databricks reads them directly through a Unity Catalog Volume.
- **Silver — Raw Vault**: dbt staging models (`stg_*`, schema `raw_vault`) type the bronze files and compute hash keys; hubs, links and satellites are then loaded on top with `dbt-databricks` + `automate_dv`. Hashing/typing is already Data Vault modeling, so it belongs to silver, not bronze.
- **Silver — Business Vault**: business rules, PIT and bridge tables for query performance.
- **Gold**: data marts (star schema) for BI consumption.

## Modeled domain

Patients, practitioners, facilities, specialties, insurance providers,
exam types, appointments and exams — each with a **status history**
(`SCHEDULED`, `CONFIRMED`, `CANCELLED`, `RESCHEDULED`, `COMPLETED`,
`NO_SHOW`) and support for **self-pay visits** (with a payment record:
method, amount and status) in addition to insurance-covered visits.

## Prerequisites (already set up outside this repo)

- GCS bucket `clinic-datavault`, with a `clinic-uploader` service account (`storage.objectAdmin` permission).
- Databricks on GCP: catalog `clinic_dv`, schemas `bronze`/`raw_vault`/`business_vault`/`gold`, external Volume `clinic_dv.bronze.raw_files` pointing to `gs://clinic-datavault/raw`.
- An active SQL Warehouse and a Personal Access Token.

## How to run

1. Create and activate a virtual environment:
   ```bash
   python -m venv .venv
   source .venv/Scripts/activate
   pip install -r requirements.txt
   ```
2. Copy `.env.example` to `.env` and fill in the values — especially
   `GOOGLE_APPLICATION_CREDENTIALS`, pointing to the service account key
   **stored outside this repository** (e.g.
   `C:/Users/<you>/.gcp-keys/clinic-uploader-key.json`).
3. Generate data locally:
   ```bash
   python -m src.generator.generate_data
   ```
   CSVs are written to `data/raw/<entity>/` (a Git-ignored folder).
4. Generate and upload to GCS in one go:
   ```bash
   python -m src.generator.generate_data --upload
   ```
   Or, if the files already exist locally, just upload:
   ```bash
   python -m src.generator.upload_to_gcs
   ```

## dbt project

The `dbt/` folder holds the transformation project. The staging layer reads
the CSVs directly from the Unity Catalog Volume (`read_files`) and adds a
hash key per business key, materializing into the `raw_vault` schema —
ready for the hub/link/satellite models that build on top of it next.

`macros/generate_schema_name.sql` overrides dbt's default behavior of
concatenating the connection schema with a model's `+schema` (which would
otherwise produce schemas like `bronze_raw_vault`); with the override, a
model's `+schema` is used as-is.

Hash key convention: `sha2(upper(trim(business_key)), 256)`. Two entities
(`appointments`, `exams`) get a type-prefixed key (`APPOINTMENT-<id>`,
`EXAM-<id>`) because `payments` references either one through the same
`reference_type` + `reference_id` pair — see the comment in
`dbt/models/staging/stg_appointments.sql` for details.

1. Install dbt (already in `requirements.txt`: `dbt-core`, `dbt-databricks`).
2. Create `~/.dbt/profiles.yml` (never committed) — replace `<...>` with the
   values from your SQL Warehouse's *Connection details*:
   ```yaml
   clinic_datavault:
     target: dev
     outputs:
       dev:
         type: databricks
         catalog: clinic_dv
         schema: raw_vault
         host: <server-hostname>
         http_path: <http-path>
         token: "{{ env_var('DBT_DATABRICKS_TOKEN') }}"
         threads: 4
   ```
   Then export your token instead of hardcoding it:
   ```bash
   export DBT_DATABRICKS_TOKEN=<your-personal-access-token>
   ```
3. From the `dbt/` folder, install packages and run the staging layer:
   ```bash
   cd dbt
   dbt deps
   dbt run --select staging
   dbt test --select staging
   ```
